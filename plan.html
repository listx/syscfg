2.1 TODO Remove the doom-themes pin from packages.el

The Emacs config pins doom-themes to upstream commit a592029 in $DOOMDIR/packages.el. Doom's own pin (in modules/ui/doom/packages.el of the emacs/doom-upstream submodule) predates the fix for doom-themes issue 875, a face inheritance cycle with gnus-group-news-low-empty that Emacs 31 rejects, so load-theme fails.

When to do it: after updating the emacs/doom-upstream submodule, check whether Doom's own doom-themes pin includes commit d114523 (which fixes the gnus-group-news-low-empty cycle). If it does, delete our (package! doom-themes :pin ...) line and its comment from emacs.org, run doom sync, and remove this entry.

2.2 DONE Replace WezTerm with Ghostty

We started trying out Ghostty as a replacement for WezTerm on 2026-11-08. Ghostty already covers the font and its cv06 feature, the window size and padding, the colors, the cursor, hiding the title bar and tab bar, Option as Alt on the Mac, the per-host font size (which xmonad passes on k0), and Nix packages for both NixOS and the Mac. xmonad already launches Ghostty. Two things still stand in the way of removing WezTerm.

2.2.1 Stop identifying as WezTerm

This was the main blocker: even inside Ghostty, our shells and tmux claimed to be WezTerm, because .zshenv exported TERM=wezterm and tmux set default-terminal to wezterm.

On 2026-11-09 we moved TERM off wezterm:

  • .zshenv no longer sets TERM (except to xterm-24bit on w0), so it's xterm-ghostty directly in Ghostty and tmux-256color inside tmux.

  • tmux gives tmux* terminals the extkeys and RGB features, so that a nested tmux in passthrough mode still gets extended keys and 24-bit color.

  • The .zshrc check that starts tmux no longer looks at TERM, which would otherwise stop tmux from starting on a remote host reached from a tmux pane.

  • WezTerm sets TERM=wezterm itself, so it keeps working as a fallback, including tmux's wezterm*:extkeys feature and the term-file-aliases entry for wezterm in the Emacs config. Emacs needs no alias for the new names, because it falls back from xterm-ghostty to its xterm support and has its own tmux support, which runs the xterm initialization (and so our modifyOtherKeys hook) too.

We tried it in Ghostty by hand on 2026-11-09 and it was good enough, though we didn't check every case. If something comes up later, these are the likeliest suspects:

  • nested tmux over ssh with passthrough mode;

  • the Mac, whose system terminfo might lack tmux-256color; and

  • ssh straight from Ghostty, outside tmux, which sends TERM=xterm-ghostty to hosts that may not have its terminfo. Ghostty's ssh-terminfo and ssh-env shell integration features can fix that if it's a problem.

2.2.2 Check the features that Ghostty doesn't replace one for one

  • Opening URLs from the keyboard: WezTerm's Open URL binding picks a URL on screen with QuickSelect and opens it. As far as we know, Ghostty only opens links by mouse click. So tmux now does it with an fzf popup, and Ghostty sends tmux a key for super+shift+y, the same key as in WezTerm.

  • Modified keys: WezTerm's config writes out CSI u sequences for the M-, C-, C-S-, C-M-, and C-M-S- letters, and for the "exotic" keys (Tab, Backspace, Enter, Space, Escape, and [ with modifiers). Ghostty sends these only when the program asks, which tmux and our Emacs do. The letter chords are already sorted out. For the exotic keys, Ghostty used to keep ctrl+tab for itself, and Emacs decoded Tab, Enter, and Escape with modifiers to control characters, so C-M-Tab looked like C-M-i. Both are fixed, and tmux's send-keys shows terminal Emacs reading them as named keys (C-M-<tab>, C-<return>, <backtab>). Ghostty also sent ctrl+backspace as ^H and dropped Shift from ctrl+shift+space, so our Ghostty config sends CSI u for those. Ghostty still sends ctrl+[ as ESC, unlike WezTerm, on purpose. We checked the keys by hand on 2026-11-09, though not every combination. Some keys that used to do nothing in terminal Emacs now run Doom's bindings, as in GUI Emacs, such as aya-create on C-<tab> and tab-previous on C-S-<tab>. We keep those.

  • The bell: WezTerm disables the audible bell. Our Ghostty config doesn't touch it, because Ghostty 1.3.1's default bell-features already includes no-audio and no-system.

2.2.3 Steps

  1. Move TERM off wezterm, then test tmux, nested tmux, and Emacs keys in Ghostty (done).

  2. Decide what to do about opening URLs from the keyboard (done).

  3. After a few more days of using Ghostty day to day, remove wezterm.org, its Makefile and Nix entries, the wezterm/upstream submodule and its line in the terminfo Makefile rule, tmux's wezterm*:extkeys feature, and the Emacs term-file-aliases entry for wezterm, and reword the prose that compares Ghostty with WezTerm (done).
