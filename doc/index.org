This repo uses [[https://lilac.funloop.org/][Lilac]] to extract the code/configuration from Org files. Not all
parts have been migrated over to use Lilac yet, and until that's done there will
be many incomplete sections in the docs.

* Installation

Each subdirectory is responsible for one component, and is also the name of a
build rule in the ~Makefile~.

E.g., to set up Emacs and Vim configurations, do:

#+begin_src sh
make emacs vim
#+end_src

* Known Issues

  - The default repository name, ~syscfg~, is hardcoded in some places.

* AI policy

AI-written code must be attributed. A commit whose diff was mostly written by an
AI must say so with a ~Co-Authored-by~ trailer that names the AI, such as
~Co-Authored-by: Claude Opus 5.5 <noreply@anthropic.com>~, so that the history
stays honest about where the code came from. The [[id:3168c3de-c577-4da3-a557-5c9b8836f386][Claude settings]] include a
commit message skill that applies this rule.

** Literate Makefile

The literate programming configuration is inside the ~doc~ folder. It houses all
Org files which we feed into Lilac to tangle the code and also weave HTML
output.

#+header: :tangle doc/Makefile
#+begin_src makefile
org_files := $(shell find . -type f -name "*.org")

obj_files := $(org_files:%.org=%.lobj)

archive_file := syscfg.larc

all: tangle weave lint
.PHONY: all

$(obj_files) &: $(org_files)
	lilac compile $?
	touch $(obj_files)

$(archive_file): $(obj_files)
	lilac archive $^ --out-file $@

tangle: $(archive_file)
	lilac tangle $< --out-dir ..
	touch tangle

weave: $(archive_file)
	lilac weave $< --out-dir site --write-css --write-js
	touch weave

The woven contents are published to ~syscfg.funloop.org~, with GitHub Pages. We
publish the contents to a separate branch ~gh-pages~ on the same repo.

#+name: Makefile:publish
#+begin_src makefile
<<Makefile:create-tarball>>

PAGES_BRANCH := gh-pages
PAGES_DOMAIN := syscfg.funloop.org
PAGES_REMOTE ?= $(shell git remote get-url $$(git config branch.main.remote) || git remote get-url origin)
PAGES_GIT_NAME  ?= $(or $(shell git config user.name),pages-publisher)
PAGES_GIT_EMAIL ?= $(or $(shell git config user.email),pages-publisher@localhost)

publish: $(archive_file) weave $(vendored)
	rm -rf site/vendor
	cp -r vendor site
	touch site/.nojekyll
	echo $(PAGES_DOMAIN) > site/CNAME
	cd site && \
		git add -A && \
		{ git diff --cached --quiet || \
		  git -c user.name="$(PAGES_GIT_NAME)" -c user.email="$(PAGES_GIT_EMAIL)" \
			commit -q -m "update"; } && \
		git push -f "$(PAGES_REMOTE)" $(PAGES_BRANCH)
	touch publish
#+end_src

The tarball is mainly composed of the site (woven contents) plus the vendored
stuff.

The vendoring is needed because originally we used to publish on SourceHut,
which does not allow us to pull in scripts from CDNs. SourceHut forced us to be
self-contained. Lilac has a ~lilac init --only-local-imports~ command which gives
us some scripts to download MathJax and also Source fonts.

Although we don't use SourceHut any more, we've kept the "let's keep things
self-contained" philosophy, for reproducibility.

#+name: vendor-mathjax.sh
#+header: :tangle doc/vendor-mathjax.sh
#+header: :shebang #!/usr/bin/env bash
#+begin_src bash
set -euo pipefail

MAIN_PACKAGE="mathjax"
FONT_PACKAGE="mathjax-newcm-font"
VERSION="4.1.2"

mkdir -p vendor
pushd vendor

download_tarball()
{
	local package
	local version
	local url_prefix
	local tarball
	package="${1:-}"
	version="${2:-}"
	tarball="${package}-${version}.tgz"
	url_prefix="${3:-}"

	if [[ -d "${package}" ]]; then
		echo "${package} directory already exists"
		return 1
	fi

	curl -OL "${url_prefix}/-/${tarball}"
	tar xzvf "${tarball}"
	mv package "${package}"
	rm "${tarball}"
}

download_tarball \
	"${MAIN_PACKAGE}" \
	"${VERSION}" \
	"https://registry.npmjs.org/mathjax"
download_tarball \
	"${FONT_PACKAGE}" \
	"${VERSION}" \
	"https://registry.npmjs.org/@mathjax/${FONT_PACKAGE}"
#+end_src

** CI

Publish the woven docs to GitHub in CI for the ~main~ branch, so that we don't
have to remember to manually invoke the publishing step from [[id:6a2b57ae-0d97-4cd0-9d48-2b9390e898ef][Publish to GitHub]].

#+name: GHA-publish
#+header: :tangle .github/workflows/publish-site.yml
#+begin_src yaml
name: Build and publish site

on:
  push:
    branches: [main]
  pull_request:
  workflow_dispatch:

permissions:
  contents: write

concurrency:
  group: publish-site-${{ github.ref }}
  cancel-in-progress: false

jobs:
  site:
    name: Build, check, and publish
    runs-on: ubuntu-latest
    steps:
      - name: Check out repository
        uses: actions/checkout@v4

      - name: Install Nix
        uses: cachix/install-nix-action@v31

      - name: Tangle, weave, and lint
        working-directory: doc
        run: nix-shell .. --run "make"

      - name: Check for uncommitted changes
        working-directory: doc
        run: |
          git diff
          if [[ -z "$(git status --porcelain)" ]]; then
            echo "Clean (no untracked files either)."
          else
            echo "Modified or untracked files present."
            exit 1
          fi

      - name: Publish to gh-pages
        if: github.ref == 'refs/heads/main'
        working-directory: doc
        env:
          PAGES_REMOTE: https://x-access-token:${{ secrets.GITHUB_TOKEN }}@github.com/${{ github.repository }}.git
          PAGES_GIT_NAME: github-actions[bot]
          PAGES_GIT_EMAIL: 41898282+github-actions[bot]@users.noreply.github.com
        run: |
          git -C site init -q -b gh-pages
          nix-shell .. --run "make publish"
#+end_src
