#+title: Notmuch

For more information about notmuch, see https://notmuchmail.org.

* Main configuration

#+header: :tangle notmuch/notmuch-config
#+begin_src ini
<<database>>
<<user>>
<<new>>
<<search>>
<<maildir>>
#+end_src

** Database

#+begin_quote
The only value supported here is 'path' which should be the top-level
directory where your mail currently exists and to where mail will be
delivered in the future. Files should be individual email messages.
Notmuch will store its database within a sub-directory of the path
configured here named ".notmuch".
#+end_quote

For us the [[database]] section is empty because we just use the default path
~\~/mail~.

#+name: database
#+begin_src ini
[database]
#+end_src

** User

#+begin_quote
Here is where you can let notmuch know how you would like to be
addressed. Valid settings are

name		Your full name.
primary_email	Your primary email address.
other_email	A list (separated by ';') of other email addresses
		at which you receive email.

Notmuch will use the various email addresses configured here when
formatting replies. It will avoid including your own addresses in the
recipient list of replies, and will set the From address based on the
address to which the original email was addressed.
#+end_quote

#+name: user
#+begin_src ini
[user]
name=Linus Arver
primary_email=linus@ucla.edu
other_email=linusarver@gmail.com
#+end_src

** ~notmuch new~

#+begin_quote
Configuration for "notmuch new"

The following options are supported here:

	tags	A list (separated by ';') of the tags that will be
		added to all messages incorporated by "notmuch new".

	ignore	A list (separated by ';') of file and directory names
		that will not be searched for messages by "notmuch new".

		NOTE: *Every* file/directory that goes by one of those
		names will be ignored, independent of its depth/location
		in the mail store.
#+end_quote

#+name: new
#+begin_src ini
[new]
tags=raw; (ref:new-raw)
#+end_src

[[(new-raw)]] tags all new mails as "raw" (unprocessed).

** Search

#+begin_quote
The following option is supported here:

	exclude_tags
		A ;-separated list of tags that will be excluded from
		search results by default.  Using an excluded tag in a
		query will override that exclusion.
#+end_quote

#+name: search
#+begin_src ini
[search]
exclude_tags=deleted;trash;spam;
#+end_src

** Maildir compatibility

#+begin_quote
The following option is supported here:

	synchronize_flags      Valid values are true and false.

	If true, then the following maildir flags (in message filenames)
	will be synchronized with the corresponding notmuch tags:

		Flag	Tag
		----	-------
		D	draft
		F	flagged
		P	passed
		R	replied
		S	unread (added when 'S' flag is not present)

	The "notmuch new" command will notice flag changes in filenames
	and update tags, while the "notmuch tag" and "notmuch restore"
	commands will notice tag changes and update flags in filenames
#+end_quote

We just use the default setting (which is ~synchronize_flags=true~).

#+name: maildir
#+begin_src ini
[maildir]
#+end_src

* Tag handling
:PROPERTIES:
:ID:       62b69a89-b413-4868-872e-00d4c1c67def
:END:

This is where we do most of the work. You can think of the settings here as an
elaborate script which tags certain emails that match the query, in
top-to-bottom order.

# but if they are filtered out of the inbox (aka "Skip the Inbox"), do not tag
# them as "inbox" because that will put them back into the Inbox, going against
# the intent of the Gmail filters.

#+name: tags
#+header: :tangle notmuch/tags
#+begin_src txt
<<tags-trash-from-gui>>
<<tags-trash-from-emacs>>
<<tags-spam>>
<<tags-sent>>
<<tags-ml-git>>
<<tags-ml-lilac>>
<<tags-ml-sourcehut>>
<<tags-ml-catchall>>
<<tags-read>>
<<tags-default-catchall>>
#+end_src

Recall that at [[(new-raw)]] we tagged all new emails as ~raw~. The goal is to get rid
of the ~raw~ tag for every email (that is, to give them some other tag that is
more meaningful that just ~raw~).

** Trash

For emails that were deleted using the web GUI (from the phone or elsewhere)
out of band, keep them in the trash.

#+name: tags-trash-from-gui
#+begin_src txt
-raw                -- tag:raw and tag:trash
#+end_src

Mark deleted emails (deleted from Notmuch via Emacs) to be moved to the trash.
We work with the "deleted" tag because the default ~d~ keybinding in Emacs for
notmuch adds the "deleted" tag (and we don't want to bother customizing that).

#+name: tags-trash-from-emacs
#+begin_src txt
+trash -inbox -deleted -- tag:deleted
#+end_src

** Spam

Skip any processing of all spam emails (by removing their ~raw~ tag). In
particular, this makes the ~+unread -raw +inbox~ rule avoid considering them,
keeping them out of the inbox.

#+name: tags-spam
#+begin_src txt
-raw                -- tag:raw and tag:spam
#+end_src

** Sent

Skip tagging of sent emails, just like how we skipped spam emails in [[tags-spam]].

#+name: tags-sent
#+begin_src txt
-raw                -- tag:raw and tag:sent
#+end_src

** Mailing lists

Tag all raw mailing list messages as being unread. It's important that we do
not tag it as ~inbox~ because that'll put it into the Inbox in Gmail the next
time ~lieer~ syncs.

#+name: tags-ml-catchall
#+begin_src txt
+unread -raw -inbox -- tag:raw and tag:list
#+end_src

*** Git

Tag all messages related to the Git mailing list. Gmail filters will tag these
with ~git~ and ~git/ci~ and so on. Here we additionally give them a ~list~ tag
so that we can search across all emails related to the mailing list at once.

#+name: tags-ml-git
#+begin_src txt
+list +git          -- tag:raw and to:git@vger.kernel.org
+list +git/ci       -- tag:raw and to:ci_activity@noreply.github.com and (to:gitgitgadget/git or to:listx/git)
+list +git/ggg      -- tag:raw and from:gitgitgadget
#+end_src

*** Lilac

Tag all messages related to the Lilac mailing list.

#+name: tags-ml-lilac
#+begin_src txt
+list +lilac -- tag:raw and 'to:"~listx/lilac@lists.sr.ht"'
+list +lilac -- tag:raw and 'from:builds@sr.ht' and 'subject:lilac'
#+end_src

We have to quote it twice like this, probably to get around the shell's
interpretation of ~\~~, as well as Notmuch's own special treatment of ~\~~. We don't
require the ~raw~ tag like we do for Git, because it looks like if we originally
send the email to the list, it won't get the ~raw~ tag.

*** SourceHut

Tag all SourceHut messages. Note the use of slashes to make the query into a
regex.

#+name: tags-ml-sourcehut
#+begin_src txt
+list +sourcehut -- tag:raw and 'to:/~sircmpwn\/.*@lists\.sr\.ht/'
+list +sourcehut -- tag:raw and 'from:builds@sr.ht' and '(subject:srht.site or subject:/.*\.sr\.ht/ or subject:core-go)'
#+end_src

** Read emails

Process read emails (don't tag already-read emails as unread).

#+name: tags-read
#+begin_src txt
-raw                -- tag:raw and (not tag:unread)
#+end_src

** Default catchall

For all remaining non-mailing list emails, tag them as "inbox" and "unread".
This puts the into the Inbox in the web view.

#+name: tags-default-catchall
#+begin_src txt
+unread -raw +inbox -- tag:raw and (not tag:list)
#+end_src

* Sync script
:PROPERTIES:
:ID:       4fe79951-cd00-4b34-bd52-0e27347a5449
:END:

Call [[https://github.com/gauteh/lieer][lieer]] to sync local notmuch database (which we processed with [[id:62b69a89-b413-4868-872e-00d4c1c67def][Tag handling]]) with Gmail.

#+header: :tangle script/mail-sync.sh
#+header: :shebang #!/usr/bin/env bash
#+begin_src bash
set -euo pipefail

# Be explicit about which Notmuch configuration we're using.
export NOTMUCH_CONFIG="${HOME}/.notmuch-config"

# If we're running inside cron, we might not be aware of the usual paths used by
# Nixpkgs. Enable them here.
export PATH="${HOME}/.nix-profile/bin:/run/current-system/sw/bin:${PATH}" # (ref:env-path)

NOTMUCH_TAGS_FILE="${HOME}/syscfg/notmuch/tags"

main()
{
    cd ~/mail/linusarver@gmail.com

    # "gmi" is a script provided by the "lieer" package. It fetches mail from
    # Gmail to disk.
    gmi sync

    # Re-index new emails.
    notmuch new

    # Tag emails.
    notmuch tag --batch --input="${NOTMUCH_TAGS_FILE}"
}

main "$@"
#+end_src

Call the above script regularly via systemd (like a cronjob) on NixOS. See
[[id:7a4cb949-a16d-48ab-9a33-43a659c93dd4::nixos/k0/configuration.nix][nixos/k0/configuration.nix]].

#+name: nix:cron-mail-sync
#+begin_src nix
systemd.user.services.notmuch-sync = {
  description = "Sync Gmail with lieer and update Notmuch index";
  serviceConfig = {
    Type = "oneshot";
    ExecStart = "/home/l/syscfg/script/mail-sync.sh";
    Environment = "PATH=/run/current-system/sw/bin:/usr/bin:/bin"; # (ref:nix:cron-mail-sync-env)
  };
};

systemd.user.timers.notmuch-sync = {
  description = "Run mail sync every 15 minutes";
  wantedBy = [ "timers.target" ];
  timerConfig = {
    OnBootSec = "2min";
    OnUnitActiveSec = "15min";
    Persistent = true;
  };
};
#+end_src

Even though the script itself sets up the PATH [[(env-path)]], we still need to give
the environment /outside/ of the script the right PATH [[(nix:cron-mail-sync-env)]]
because the script's first line ~/usr/bin/env~ needs to be able to find ~bash~ (it
won't work without [[(nix:cron-mail-sync-env)]]).

To make the job run immediately, do

#+begin_src bash
systemctl --user start notmuch-sync.service
#+end_src

To stream the logs, do

#+begin_src bash
journalctl --user -u notmuch-sync.service -f
#+end_src
